# Half-Blood Prince: full-project architecture

**Status:** target architecture for the finished open-source product  
**Date:** 2026-07-11  
**Audience:** maintainers, contributors, provider-adapter authors, and renderer authors

## 1. Vision and scope

Half-Blood Prince should be a local-first command-line application and Python library that turns a PDF or EPUB into an annotated edition: terse, expert marginalia generated by a user-selected LLM, then rendered as real pen strokes rather than rotated cursive type. A successful release must work with a premium hosted model, a cheap OpenRouter model, an arbitrary OpenAI-compatible endpoint, or a local Ollama/LM Studio model without changing the extraction or rendering pipeline.

The finished product is not an AI reader, chat application, document editor, or agent framework. Its core remains a comprehensible batch pipeline:

1. extract stable document units and targetable text;
2. ask a stateless language model for a semantic annotation plan;
3. validate, locate, and lay out the plan;
4. synthesize a deterministic ink scene;
5. render that same scene into PDF, EPUB, or an interactive web preview.

The product should preserve originals, operate offline when a local model is selected, expose cost and failure information, and produce reproducible output when given the same plan, style profile, renderer version, and seed. It should remain useful when premium handwriting synthesis is unavailable: the baseline renderer will still draw actual vector pen paths, not substitute a cursive text font silently.

### Product boundaries

In scope for 1.0:

- PDF and EPUB input; annotated PDF/EPUB output; HTML preview from a saved plan.
- Anthropic, OpenAI, OpenRouter, arbitrary OpenAI-compatible servers, Ollama, and LM Studio.
- An auditable structured-output negotiation path and explicit provider capability reporting.
- Real vector handwriting, rough target marks, doodles, connectors, layout/collision handling, and deterministic seeds.
- Resumable generation, bounded concurrency, per-page status, token/cost reporting where available, and a serialized intermediate plan.
- A documented Python API, stable CLI, quality evaluation, accessibility-conscious web output, and a reproducible release process.

Out of scope for 1.0:

- DRM removal, OCR of image-only books, collaborative cloud storage, a hosted SaaS, or an in-browser EPUB reader.
- Training and distributing an unlicensed handwriting neural network.
- Reproducing a real living person's handwriting or promising forensic authenticity. The supplied style is fictionalized marginalia, and custom styles should carry an anti-impersonation warning.
- LangChain/LlamaIndex-style orchestration. This is still one structured request per document unit.

The project name and default persona evoke a copyrighted fictional work. Before a broad release, maintainers should obtain legal advice on trademark/fan-work positioning. The code and generic persona system should not require copyrighted text, logos, film artwork, or proprietary fonts; documentation should describe the default as “Snape-inspired fictional marginalia” and foreground custom personas.

## 2. Current architecture, as implemented

The current code has a sound extract → generate → render direction, but several boundaries are implicit and renderer styling is duplicated.

### 2.1 Shared contract

`src/halfblood/models.py` defines four Pydantic v2 types:

- `AnnotationType`: eight semantic categories.
- `Annotation`: 1-indexed `page`, verbatim `target_text`, type, note `content`, confidence, and one of four requested positions.
- `AnnotatedPage`: page number, original extracted text, annotations.
- `AnnotationPlan`: title, persona, pages, and a computed total.

Mutable list defaults rely on Pydantic's copying behavior but should still become `Field(default_factory=list)`. The model currently mixes semantic intent (`annotation_type`, content) with a weak layout hint (`position`). It contains no stable annotation ID, source locator, plan/schema version, generation provenance, render seed, explicit mark instruction, or style profile.

`PageContent` is a dataclass in `document_processor.py`, even though EPUB and generation also import it. Its `width` and `height` are real PDF dimensions but nominal placeholders for EPUB chapters. That leak should be removed.

### 2.2 Generation

`src/halfblood/annotation_generator.py` directly creates `anthropic.Anthropic` and sends one synchronous request per nonblank page. It forces the `record_annotations` tool and parses the matching `tool_use` block. `_ANNOTATION_TOOL_SCHEMA` is hand-maintained, although its annotation-type enum is derived from `AnnotationType`. Each item is then validated with Pydantic; invalid items are logged and dropped.

`generate_for_document` is sequential. It supplies the previous 500 characters, next 500 characters, and the latest eight prior invention/warning notes as context. It retains the highest-confidence annotations when the response exceeds the page cap. The already-merged failure work records `failed_pages`, continues after partial API failures, and raises `AllPagesFailedError` when every attempted page fails. Blank pages are neither attempts nor failures.

The current default `claude-sonnet-5`, eval extra, single-sourced model default, and failure surfacing are the merged AUD-01/02/03/04/16 batch. They are current-state facts, not future roadmap work.

### 2.3 PDF

`src/halfblood/document_processor.py` uses PyMuPDF for extraction, `search_for`, native PDF annotations, and drawn text/shapes. Text matching normalizes punctuation and whitespace, then falls back through prefixes and the longest word. `find_text_rect` unions every hit for a variant; on repeated fallback words this can create a page-spanning false target.

Margin notes are word-wrapped and inserted with a handwriting font or `Helvetica-Oblique`; a deterministic 1–3° rotation is applied to each line. This is typesetting, not handwriting synthesis. Underlines, highlights, circles, and strikeouts are perfect native PDF annotations. Connectors use a single bowed curve and two straight arrowhead segments. Placement has no occupancy model and known page-boundary bugs.

PyMuPDF remains the right PDF foundation: it combines extraction, search, vector drawing, and optional native annotations. ReportLab/pypdf would split those responsibilities and make coordinate preservation harder. The target architecture changes what is drawn, not the library.

### 2.4 EPUB

`src/halfblood/epub_processor.py` treats each linear spine XHTML item as a page-like unit, injects CSS, wraps a located text-node slice in a target span, and inserts a floated/inline note span. It correctly skips `linear="no"` spine items and works around missing EbookLib TOC UIDs. Matching only works inside one `NavigableString`; targets spanning inline markup fail. Smart punctuation is normalized in the target but not consistently in node content.

Notes use CSS cursive-family hints and rotation. Marks are CSS borders/backgrounds/text decoration. There are no SVG ink paths. Reader CSS support varies, so the existing inline-note fallback is an important compatibility behavior to preserve.

### 2.5 Web preview

`src/halfblood/web_preview.py` builds a single HTML file with embedded CSS, JavaScript, escaped plan data, target `<mark>` elements, margin collision adjustment, and SVG quadratic connector paths. Notes reveal with a clip-path animation but are Caveat web-font text. The HTML claims to be self-contained while loading Caveat and EB Garamond from Google Fonts. Its target regex needs the coupled AUD-06 correctness/complexity fix. It has no tests.

### 2.6 CLI and evaluation

`src/halfblood/cli.py` exposes `annotate`, `preview`, `web-preview`, and `eval`. PDF/EPUB dispatch is extension-based, provider configuration is absent, progress advances only after a whole generation loop, and there is no persisted plan/resume boundary. Output overwrite is implicit.

`eval/eval_harness.py` defines five cases and an LLM judge for voice consistency, relevance, insight depth, variety, and density. It duplicates an Anthropic fallback generator and judge schema. The fallback undermines a single provider seam and should be removed once the package is installable; generation and judging should independently select providers/models, and releases should pin an eval fixture and judge configuration.

## 3. Target architecture

The central design choice is to separate **semantic plan**, **resolved layout**, and **render style**. The LLM decides what to say and what source text it refers to. Deterministic local code decides where it fits and what pen paths represent it. Providers never emit coordinates, colors, SVG, or handwriting instructions.

```text
                        config + CLI / Python API
                                  |
                                  v
 PDF / EPUB --> DocumentSource --> DocumentUnit[]
                                  |
                                  v
                         AnnotationService
                    prompt + context + budgeting
                                  |
                                  v
                LLMProvider + StructuredOutputPolicy
         Anthropic | OpenAI compat | OpenRouter | Ollama/LM Studio
                                  |
                                  v
                    semantic AnnotationPlan (JSON)
                                  |
                    TargetLocator + PlanValidator
                                  |
                                  v
                 ResolvedPlan (anchors + layout boxes)
                                  |
                InkComposer + HandwritingEngine
                                  |
                                  v

                    /             |              \
                   v              v               v
            PdfRenderer      EpubRenderer     WebRenderer
```

### 3.2 Core interfaces

The following are conceptual typed contracts; exact names may evolve during implementation.

```python
class LLMProvider(Protocol):
    @property
    def capabilities(self) -> ProviderCapabilities: ...
    def complete(self, request: GenerationRequest) -> GenerationResult: ...

class DocumentSource(Protocol):
    def load(self, path: Path) -> Document: ...
    def locate(self, unit: DocumentUnit, anchor: TextAnchor) -> ResolvedAnchor: ...

class HandwritingEngine(Protocol):
    def synthesize(self, text: str, constraints: TextBox,
                   style: HandwritingStyle, seed: int) -> StrokeGroup: ...

class SurfaceRenderer(Protocol):
    def render(self, source: Document, plan: ResolvedPlan,
               scenes: Sequence[InkScene], output: Path) -> RenderReport: ...
```

`GenerationResult` includes raw provider request ID, normalized finish reason, usage, latency, chosen structured-output mode, and the parsed object. `RenderReport` includes rendered/skipped annotations, anchor/layout warnings, output hashes, and degradation flags. Secrets never appear in either.

## 4. R1: provider-agnostic LLM layer

### 4.1 Recommendation

Implement a small internal provider layer using `httpx`, with exactly two wire adapters: native Anthropic Messages and OpenAI-compatible Chat Completions. Do **not** adopt LiteLLM or an agent framework.

Why `httpx` rather than adding both vendor SDKs:

- The wire surface needed here is small: one non-streaming structured completion, error bodies, headers, and usage.
- OpenAI-compatible servers frequently diverge from a particular `openai` SDK's validation assumptions. Sending documented JSON directly is more tolerant and easier to inspect.
- A single HTTP dependency supports sync now and async later, uniform timeouts, connection pooling, retries, mock transports, and redacted debug logging.
- It preserves the repository's direct-SDK/no-framework intent: payload construction and response parsing remain visible.

Keep `anthropic` as an optional compatibility extra for one deprecation cycle only if external callers depend on injecting an Anthropic client; the production adapter should move to HTTP. A reasonable alternative is retaining the direct Anthropic SDK and using `httpx` only for OpenAI compatibility, but then retry/timeout behavior differs subtly across providers. Uniform HTTP is the cleaner finished architecture.

LiteLLM offers breadth but adds a large, fast-moving translation layer, makes capability decisions less auditable, and solves many features this product does not use. Reconsider it only if maintainers commit to dozens of non-OpenAI-shaped APIs. Anthropic plus the OpenAI-compatible protocol already covers the stated product.

### 4.2 Canonical schema

`generation/schema.py` must derive the schema from Pydantic rather than maintain a second hand-written contract:

1. Define an internal `RecordAnnotations` model with `annotations: list[AnnotationDraft]`.
2. `AnnotationDraft` excludes server-owned fields such as `id`, resolved page locator, provenance, style, and seed. Its `target_text`, `content`, enum, confidence, and requested placement are the generation fields.
3. Generate Draft 2020-12 JSON Schema via `RecordAnnotations.model_json_schema()`.
4. Normalize it for provider compatibility: inline local `$defs` references, set `additionalProperties: false` recursively, make every expected field required (defaults are filled after parsing only when deliberately supported), preserve enum/min/max/minLength constraints, and use a stable title/name `record_annotations`.
5. Hash the canonical JSON and include `schema_version`/hash in provenance and caches.

The final Pydantic validation is mandatory regardless of provider claims. Provider-side schema enforcement is an optimization and reliability aid, not a trust boundary. `target_text` and `content` require stripped `min_length=1`; page number is supplied by the caller, never trusted from model output.

### 4.3 Structured-output negotiation

`StructuredOutputPolicy` chooses the first allowed mode supported by the endpoint/model profile. `auto` order should be **forced tool/function → strict JSON Schema response format → prompt JSON**, because forced functions have the broadest real-world OpenRouter/OpenAI-compatible coverage and match current behavior. Users may pin `--structured-output tool|json-schema|prompt|auto` when capability autodetection is wrong.

#### Anthropic

- Send `tools=[{"name":"record_annotations", "input_schema": schema, ...}]` and `tool_choice={"type":"tool","name":"record_annotations"}`.
- Require exactly one matching `tool_use` block. Ignore unrelated text blocks but record their presence as a protocol warning.
- Read its object input directly, validate it, and reject `max_tokens`/truncated responses as `IncompleteResponseError`; an empty annotation list is valid only when the enclosing object and finish reason are valid.

#### OpenAI, OpenRouter, and compatible function calling

- Send `tools=[{"type":"function","function":{"name":"record_annotations","description":...,"parameters":schema,"strict":true}}]` where strict is supported.
- Force `tool_choice={"type":"function","function":{"name":"record_annotations"}}` and set `parallel_tool_calls=false` where accepted.
- Parse exactly one matching `message.tool_calls[*].function.arguments`. Arguments are a JSON string on the OpenAI protocol; parse with a size/depth-limited JSON decoder and validate.
- Some OpenRouter-routed models ignore `strict`, return legacy `function_call`, or do not support tools. The adapter handles the legacy response shape but never silently changes strategies within a billable request. A capability-related 400 can trigger one explicitly recorded strategy downgrade if policy is `auto`; content/schema errors do not cause another paid call by default.

#### JSON Schema response format

- Send `response_format={"type":"json_schema","json_schema":{"name":"record_annotations","strict":true,"schema":schema}}`.
- Parse `message.content` as the single JSON document. Handle refusal fields and incomplete finish reasons separately from malformed JSON.
- Use this mode when a known model profile supports strict schema but not tools, or when the user pins it. For providers that implement the newer Responses API later, add a wire adapter only when it provides material reliability; do not leak that API shape into `AnnotationGenerator`.

#### Prompt-and-parse fallback

- Put the minified canonical schema and one compact valid example in the system/user instruction, demand one JSON object and no fences, and set a JSON MIME/format hint if the server exposes one.
- Extract conservatively: accept a full JSON object; otherwise allow one fenced `json` block or the first balanced top-level object using a state-machine scanner. Never use a greedy regex, `eval`, JSON5, or arbitrary “repair” that changes values.
- Enforce response byte size, nesting, item count, string length, and Pydantic validation. A single local syntactic cleanup may remove BOM/fences/trailing prose. Semantic repair is a separate opt-in second model call (`--repair-structured-output`) because it costs money and can alter content.
- Mark results with `structured_output_mode="prompt"` and a reliability warning. `--strict-structured-output` disables this fallback.

Ollama's OpenAI-compatible `/v1/chat/completions` and LM Studio's compatible server use the same adapter. Known profiles may select their native JSON-schema format only if it is more reliable, but “local” is configuration, not a separate provider implementation. The CLI should print the selected mode before generation.

### 4.4 Provider profiles and configuration

Provider names are presets, not separate abstractions:

|---|---|---|---|
| `anthropic` | `https://api.anthropic.com` | `ANTHROPIC_API_KEY` | forced tool |
| `openai` | `https://api.openai.com/v1` | `OPENAI_API_KEY` | forced function |
| `openrouter` | `https://openrouter.ai/api/v1` | `OPENROUTER_API_KEY` | forced function |
| `ollama` | `http://127.0.0.1:11434/v1` | none | capability/profile dependent |
| `lmstudio` | `http://127.0.0.1:1234/v1` | none | capability/profile dependent |
| `openai-compatible` | required | `HALFBLOOD_API_KEY` or none | auto |

Resolution precedence is CLI flag → environment → project config → user config → provider preset. Read `halfblood.toml` in the working/project directory and the platform user config (`~/.config/halfblood/config.toml` on Linux, appropriate `platformdirs` paths elsewhere). Do not auto-load `.env`; users can use their shell or an optional launcher.

`--base-url` must accept HTTP for loopback/local endpoints but require HTTPS for non-loopback hosts unless `--allow-insecure-http` is explicit. Strip credentials and query secrets from logs. OpenRouter attribution headers (`HTTP-Referer`, `X-Title`) are optional config. A `halfblood providers doctor` command should make a minimal, clearly disclosed request (or perform a no-network config check with `--offline`), report endpoint/model/capabilities, and redact keys.

There should be no universal model default across providers. Provider presets may recommend a model, but `model` must be explicit unless a provider-specific default is known and versioned. This avoids recreating the retired-model failure. `halfblood config show` prints effective nonsecret settings and sources.

### 4.5 Dependencies

Core dependencies should include `httpx`, Pydantic, Click, Rich, and the document stack. Proposed extras:

- `[pdf]`: PyMuPDF (core in 1.0 if PDF remains the primary experience).
- `[epub]`: EbookLib, BeautifulSoup, lxml.
- `[handwriting]`: ONNX Runtime plus a separately licensed model asset installer; not required for procedural strokes.
- `[eval]`: test/evaluation reporting dependencies only; provider transport is core.
- `[dev]`: pytest, pytest-cov, respx or `httpx.MockTransport`, mypy, Ruff, Playwright, build, twine, and snapshot tooling.

Avoid the `openai`, `anthropic`, and LiteLLM runtime packages unless a demonstrated protocol feature cannot be supported cleanly via HTTP. Pin compatible upper bounds for 1.0 and maintain a locked development environment using `uv.lock`; libraries still publish sensible ranges rather than a fully frozen transitive graph.

### 4.6 Errors, retries, concurrency, and failure composition

Normalize transport details into a small taxonomy:

- `ProviderConfigurationError`: missing key, invalid base URL, unknown profile/model; never retry.
- `ProviderAuthenticationError` (401/403): never retry.
- `ProviderNotFoundError` (404 model/endpoint): never retry.
- `ProviderCapabilityError` (unsupported tools/schema): one strategy downgrade only under `auto`; otherwise never retry.
- `ProviderRateLimitError` (429): retry according to `Retry-After`, rate-limit headers, and budget.
- `ProviderTransientError` (408/409/425/5xx, connection reset/timeout): bounded retry.
- `ProviderSafetyRefusal`: page failure, normally not retryable.
- `IncompleteResponseError`: retry once with a larger token budget within configured cap.
- `StructuredOutputError`: optionally one repair/regeneration attempt, then page failure.
- `AnnotationValidationError`: item-level drops are allowed up to a threshold; a wholly invalid response is a page failure.

Use exponential backoff with full jitter, honor `Retry-After`, cap attempts and elapsed time, and expose attempts in `PageGenerationStatus`. Retrying must be owned by the provider layer so an SDK cannot also retry invisibly. OpenAI-compatible POSTs are not assumed idempotent; a retry may incur cost, which is reported. A configurable document request/token/cost budget stops scheduling new pages before overspend.

Replace `failed_pages: list[int]` with a `GenerationReport` containing status for every unit, while keeping `failed_pages` as a compatibility property. Preserve the merged semantics:

- blank/skipped units are not failures;
- partial failures return a plan plus report and make the CLI warn (optionally nonzero under `--fail-on-partial`);
- every attempted unit failing raises an evolved `AllPagesFailedError(report)`;
- provider-independent errors flow through the same mechanism;
- a valid empty `annotations` array is success, not failure.

Add bounded async generation after correctness: `httpx.AsyncClient`, a global semaphore, and an adaptive provider rate limiter. Because running notes introduce ordering, use **windowed concurrency**: generate a small batch against the same committed prior context, then fold results into running notes in page order before scheduling the next batch. `--concurrency 1` remains the deterministic baseline. Save each successful page atomically to a `.halfblood-work/` checkpoint keyed by source hash, prompt/schema version, provider/model, and relevant config; `--resume` never repeats a paid call whose validated result is cached.

## 5. R2: genuine handwriting and ink

### 5.1 Recommendation

Generate a surface-neutral `InkScene` once, then render its vector paths on every surface. Ship a deterministic **procedural centerline-stroke handwriting engine** as the zero-model default, with multiple authored letter/ligature variants and pen-trajectory perturbation. Offer an optional **ONNX pen-trajectory synthesis engine** for higher naturalism only after a model and training data pass licensing/provenance review.

This recommendation deliberately rejects “just perturb font outlines.” Outline deformation still fills closed glyph silhouettes, repeats recognizable type shapes, and cannot produce convincing pen lifts, joins, pressure, or stroke order. It also rejects making a Graves-style neural model mandatory: available packages are often old TensorFlow research code, weights/data have uncertain redistribution rights, CPU cost is significant at book scale, and unconstrained synthesis can sacrifice legibility. Neural trajectories are valuable as an optional engine, not the product's legal or operational foundation.

An SVG “stroke font” is acceptable only as raw trajectory data, not as browser/PDF text. The shipped engine should consume authored centerlines with stroke order, alternates, entry/exit points, and pen lifts; compose them contextually; then apply word-level baseline drift, slant variation, spacing compression, imperfect joins, tremor, speed/pressure curves, and occasional retracing. The result is a set of actual strokes and differs per occurrence while staying legible. Assets must be created for this project or imported under a clearly compatible license with attribution and redistribution rights.

### 5.2 Ink scene model

All coordinates are in a normalized local unit and transformed into PDF points/CSS pixels/EPUB viewBox units at render time.

```text
InkScene
  version, annotation_id, seed, bounds, degradation_flags
  groups[]
    role: handwriting | underline | circle | strike | caret | connector | doodle
    paths[]
      commands: MoveTo | LineTo | CubicTo
      samples?: (x, y, pressure, time, pen_down)[]
      stroke: color, base_width, opacity, cap=round, join=round
      width_profile: sampled relative widths along arc length
      transform, z_index, accessibility_label
```

`InkComposer` receives a resolved annotation, its note box and target quads, a style profile, and a seed. It asks `HandwritingEngine` for note strokes and `RoughStrokeGenerator` for marks/connectors. It clips and validates bounds, simplifies paths with a tolerance smaller than the thinnest visible nib, and returns one immutable scene. Renderers are translators only; they must not invent different jitter.

Scene generation uses a stable, documented PRNG such as PCG64 with labeled sub-seeds derived by BLAKE2b from `(document_seed, annotation_id, role, algorithm_version)`. Never use Python's process-dependent `hash()`. Adding a doodle must not change the note's letters because each role has an independent substream. Store `render_seed` and `ink_algorithm_version`; store scenes in checkpoints/cache when exact cross-version reproduction matters.

### 5.3 Letterform engines

#### Shipped `ProceduralStrokeHandwriter`

- Assets: lowercase/uppercase/digits/punctuation centerline strokes, at least 3–5 common-letter alternates, initial/medial/final forms, common ligatures, and explicit metrics/anchors.
- Composition: choose contextual variants; join where exit/entry geometry permits; preserve pen lifts; shape words as units rather than independently rotating characters.
- Natural variation: low-frequency baseline and slant curves, correlated character scale/spacing, bounded control-point noise, pressure based on speed/curvature, ink pooling at slow starts/stops, and rare configured imperfections. Noise must be correlated; independent point jitter looks like a broken plotter.
- Layout: measure synthesized trajectory bounds, line-break at words, resynthesize each line with continuation state, and retry at smaller scale within configured readability limits.
- Performance: cache canonical word trajectories by `(engine version, style, normalized word, seed)` and transformed note scenes by content/style/box/seed. Synthesis is CPU-light and offline.
- Coverage: unsupported Unicode uses an explicit fallback run and records a degradation. The first release should fully cover Latin-1 punctuation; broader scripts require authored trajectory packs.

#### Optional `OnnxTrajectoryHandwriter`

- Input text plus style vector; output `(dx, dy, pen_state[, pressure])` samples, converted to smoothed cubic paths.
- Run through ONNX Runtime CPU with batched note strings. Model download is explicit, checksummed, cached under `platformdirs`, and accompanied by model/data license and provenance metadata.
- Guard maximum text length, time, output points, bounds, self-intersection extremes, and legibility. Fall back per note to procedural strokes on model load/inference/quality failure, with a report warning.
- A custom user model path is supported, but compatibility is validated via a manifest. The project must not imply arbitrary Graves repositories are safe to redistribute.

#### Font fallback

A font is no longer the normal fallback. `--handwriting-engine font` is an explicit compatibility/debug mode for legacy output. If procedural assets are unexpectedly missing, fail clearly for final renders unless `--allow-typeset-fallback` was supplied. Web/EPUB can also expose the note content as visually hidden/selectable accessible text even when the visible note is paths.

### 5.4 Marks, doodles, and connectors

`RoughStrokeGenerator` constructs all non-letter ink from the same seeded pen model:

- Underline: one or two imperfect passes following target line quads, with overshoot, changing pressure, and a gap at line wraps.
- Circle: an open, slightly overshooting irregular loop around each logical target cluster; never a perfect ellipse.
- Strike-through: one decisive or two agitated strokes across each text line, varied by annotation type/style.
- Highlight/emphasis: translucent broad-nib strokes behind text with ragged ends; warnings may combine this with a thin rough outline.
- Caret: two quick strokes and an insertion stem placed in a real interline gap.
- Connector: a cubic path seeded from the existing bowed-curve concept, with low-frequency wobble, variable width, an imperfect two-stroke arrowhead, and obstacle-aware routing from the note edge to the nearest target edge.
- Doodles: a small, curated, parameterized vocabulary (stars, cauldrons, arrows, question marks, potion bubbles), selected only for `DOODLE_NOTE` or explicit mark intent; the LLM may request a semantic doodle kind but never raw SVG.

Variable width is represented in the scene independent of renderer. When a surface cannot stroke a path with a width profile, `StrokeExpander` converts the centerline and width samples to a filled outline polygon. This is the common high-fidelity path for PDF and EPUB and prevents each renderer from approximating pressure differently.

### 5.5 Layout and target marks

Before ink synthesis, `LayoutEngine` resolves position hints against real constraints:

- Represent source targets as character ranges plus one or more line quads, not a single union rectangle.
- Rank matching candidates using exactness, surrounding context, page/chapter offset, line continuity, and uniqueness. Ambiguous low-score matches are skipped/reported rather than guessed.
- Maintain per-side vertical interval occupancy. Place high-priority notes first, solve remaining notes with bounded shifting/side switching/font scaling, and route connectors around note boxes and target text.
- Honor page bounds and minimum readable scale; move `inline`/`between_lines` requests to a margin if no safe gap exists.
- Keep semantic requested position separate from resolved placement and record reasons for fallback.

This directly fixes the current overflow/collision class and makes handwriting measurement part of layout rather than an afterthought.

### 5.6 PDF rendering

`PdfRenderer` uses PyMuPDF `Shape.draw_line`/`draw_curve` for constant-width paths and filled outline polygons for pressure-varying strokes, then commits them as an overlay. Notes, marks, doodles, and connectors are all derived from the same `InkScene`.

Default output should use flattened vector ink for visual fidelity. Native underline/highlight/circle annotations cannot express wobble or variable width, so they are no longer the visible mark. An optional `--pdf-native-annotations` accessibility/editability mode may add invisible or low-opacity native annotations with the note content as metadata, behind the visible vector ink. Document the tradeoff: native editability versus exact appearance. Preserve original page boxes, rotations, links, metadata, and incremental safety; save to a new output file atomically.

PDF path count can become large. Simplify trajectories, merge adjacent same-style filled segments, reuse form XObjects only where doing so does not visibly repeat handwriting, and enforce per-note/path limits. Benchmark 300-page books for size, render time, and viewer performance.

### 5.7 Web preview rendering

Embed generated scenes as SVG paths with `vector-effect="non-scaling-stroke"` where appropriate and filled outlines for pressure strokes. Each note has:

- visible SVG paths;
- an escaped accessible text element/HTML sibling carrying the original content;
- target and connector association by stable annotation ID;
- draw-on animation using stroke dash offsets for centerlines or masks for filled strokes;
- `prefers-reduced-motion` behavior that shows complete ink immediately.

Do not make rough.js a runtime dependency. Rough.js is excellent for procedural shapes, but generating wobble again in the browser would break cross-surface identity and reproducibility. Its algorithms may inspire or be vendored into the Python rough generator only after license review. The HTML should embed all required assets, remove Google Font requests, escape JSON safely including `</script>` and U+2028/U+2029, and keep connectors responsive by transforming/re-routing endpoints without changing their seeded wobble profile.

### 5.8 EPUB rendering

EPUB uses inline SVG because it is part of EPUB 3 and retains vector paths, but reader support and layout are less uniform than browsers:

- Wrap the target using a DOM-range locator capable of spanning inline tags without destroying markup.
- Insert an `<aside epub:type="annotation">` containing a sized inline `<svg viewBox=...>` for handwriting plus a visually hidden/plain-text note for accessibility and search.
- Render marks as inline SVG overlays/backgrounds only when the target geometry is reliable. Reflow means exact multi-line geometry cannot be known at build time; for maximum compatibility, apply a rough SVG underline as a repeatable/background decoration or retain a conservative CSS target style while the note itself is true stroke handwriting.
- Connectors are omitted by default in reflowable EPUB because note and target geometry changes by reader. On readers supporting modern CSS, a progressive-enhancement connector may appear; its absence is an intentional degradation, not a different semantic plan.
- Provide compatibility modes: `svg` (default), `hybrid` (SVG notes + CSS marks), and `text` (plain accessible note, legacy cursive only if explicitly requested). Test Apple Books, Calibre, Thorium, and at least one Kindle conversion path; document the matrix rather than promise universal float/SVG behavior.

Embed only assets actually used. The procedural engine needs no font. If an optional fallback font is embedded, subset it and include the license. EPUB output must remain valid XHTML/XML, preserve spine/TOC/media, and inject CSS/assets exactly once.

### 5.9 Graceful degradation and performance

Degradation is explicit in `RenderReport` and CLI output:

1. ONNX unavailable/fails → procedural vector strokes.
2. A glyph is unsupported → explicit licensed fallback glyph paths or, with permission, typeset fallback for that run.
3. EPUB lacks reliable target geometry → SVG note + conservative CSS mark, no connector.
4. SVG is unsupported in a target reader profile → accessible text note with CSS mark.
5. A note cannot fit at readable size → switch side/placement; if still impossible, skip and report rather than draw off-page.

Compose scenes in parallel by annotation after layout, batch neural inference, cache results by content hash, and stream pages to renderers. Do not hold decoded copies of every page or browser-sized raster snapshots in memory. Establish budgets for maximum strokes/points per note and maximum output expansion.

## 6. Data model and pipeline evolution

### 6.1 Semantic v2 plan

The saved plan must remain portable and renderer-independent:

```text
AnnotationPlan
  schema_version: "2.0"
  id, title, persona
  source: fingerprint, media_type, unit_count
  generation: provider, base_url_origin, model, prompt_version,
              schema_hash, structured_output_mode, timestamp, usage
  document_seed: uint64
  pages/units[]
    unit_id, ordinal, label, original_text, source_locator
    status
    annotations[]
      id: stable UUIDv5/content-derived ID
      target: quote, prefix, suffix, normalized offsets when known
      annotation_type, content, confidence
      requested_placement
      mark_intent: underline|circle|strike|highlight|caret|none
      doodle_kind?: enum
```

Use a `TextQuoteSelector`-style target (`exact`, `prefix`, `suffix`) plus optional extracted-text offsets. This disambiguates repeated phrases and survives renderer-specific geometry. The provider produces only `exact` and semantic fields; local code adds context/offsets and IDs.

Do not store colors, SVG, font sizes, or resolved coordinates in `Annotation`. A separate optional render manifest records:

```text
ResolvedPlan
  semantic_plan_hash, source_fingerprint, layout_version, style_id/version
  annotations[]: resolved source ranges/quads, note box, resolved placement,
                 render_seed, warnings
```

`InkScene` is a third cache/artifact, not part of the semantic API response. This separation lets users re-render the same paid generation in another style or format without another LLM call.

### 6.2 Migration and serialization

- Add `schema_version`; treat absent as v1.
- Provide pure migrations `v1 -> v2`, assigning deterministic IDs/seeds and converting `position` to `requested_placement`.
- Serialize JSON deterministically for hashing; preserve unknown future fields only through an explicit compatibility envelope, not Pydantic's default silent ignore.
- Add `halfblood plan validate`, `plan migrate`, and `render PLAN --source BOOK` commands.
- `annotate` becomes a convenience composition of `generate` and `render`; `generate` always has an option to save the plan, and `render` never needs an API key.

## 7. Testing and quality strategy

### 7.1 Provider tests

Use `httpx.MockTransport` (or respx) with checked-in JSON fixtures. No unit test contacts a provider.

For every adapter/strategy, assert exact request method/path/headers after redaction, schema mapping, tool forcing, legacy response handling, refusal/truncation, malformed arguments, empty success, usage normalization, and finish-reason mapping. Contract suites should run the same scenarios against Anthropic and OpenAI-compatible adapters. Retry tests use an injected clock/PRNG and cover `Retry-After`, no-retry statuses, attempt/elapsed budgets, strategy downgrade, and duplicate-cost reporting. Test Ollama/LM Studio/OpenRouter as profiles of the same wire adapter.

Add opt-in live smoke tests, guarded by environment variables, never run on forks, with a one-page token/cost ceiling. Record sanitized provider/model/version results but not response content from copyrighted fixtures. The eval harness must consume `LLMProvider`; delete its inline Anthropic fallback. Select a different judge family/provider where practical (AUD-34), pin the rubric/prompt, and store trend artifacts rather than treating one nondeterministic run as an absolute truth.

### 7.2 Ink and layout tests

- Golden geometry tests serialize rounded `InkScene` commands for fixed seed/text/style; compare structural hashes and human-reviewable SVG artifacts.
- Invariant/property tests assert finite coordinates, in-bounds scenes, nonempty pen-down segments, width/opacity ranges, stable sub-seeds, no accidental dependence on Python hash/random global state, and bounded point counts.
- Layout fixtures cover every edge/corner, long notes, unbreakable tokens, multiple nearby targets, repeated source text, rotated/cropped PDF pages, and crossed-out placement.
- Render the same scene to SVG and PDF, extract/normalize their paths, and compare endpoints/bounds within tolerance. Do not byte-snapshot PDFs; metadata and object ordering are unstable.
- Visual regression rasterizes a small licensed/public-domain fixture at a pinned DPI and uses perceptual diff with tight masks/tolerances. Golden updates require explicit maintainer review.
- Performance tests synthesize/render representative 300-page plans and enforce time, peak memory, path count, and output-size budgets.
- Optional ONNX tests use a tiny redistributable test model or mocked engine; full-model tests are opt-in and checksum pinned.

### 7.3 PDF, EPUB, and web coverage

PDF tests retain extraction/native-content assertions and add source-preservation, atomic-output, page bounds, multi-quad anchors, and vector-path checks.

EPUB currently has zero coverage (AUD-24). Add fixture-based load, nav skipping, smart-quote matching, cross-tag DOM ranges, rendering multiple annotations in one node, XHTML validation with lxml, roundtrip spine/TOC/resource preservation, CSS/SVG injection-once, accessibility text, malicious-content escaping, and all compatibility modes. Unzip and inspect the artifact rather than checking only that a file exists.

Web currently has zero coverage (AUD-25). Add Python tests for matching/escaping/payloads and Playwright tests for page navigation, filters, anchoring, resize, dark mode, keyboard behavior, reduced motion, no network requests, accessible note text, and connector/path animation. Fix AUD-06's whitespace matching and complexity guard together. Use a linear normalized-text matcher or bounded literal candidate search instead of a user-derived backtracking regex.

### 7.4 General gates

CI on Linux/macOS/Windows and supported Python versions runs Ruff, mypy, pytest with coverage thresholds by package, build/install smoke tests, and artifact validation. A slower nightly job runs Playwright, render goldens, dependency/security scans, and performance smoke tests. Release CI builds sdist/wheel from a clean checkout, installs each, runs CLI smoke tests, checks metadata/licenses with `twine check`, and signs/provenances artifacts.

The current repository test command could not be executed in the design environment because the system Python lacks `anthropic` and `fitz`; collection stops before tests run. The finished contributor workflow must make this avoidable with a locked `uv sync --all-extras --dev` (and documented pip equivalent).

## 10. Open questions, risks, and explicit tradeoffs

1. **Stroke asset authorship and license is the main handwriting release blocker.** Commission/project-author a trajectory alphabet or verify a compatible source before implementation depends on it. A font license does not automatically settle derived centerline data.
2. **Neural model provenance may prevent bundled “premium” synthesis.** The product remains genuine-stroke without it; do not lower the licensing bar to meet a visual milestone.
3. **EPUB cannot guarantee fixed geometry.** True handwritten note paths are achievable, but arrows and exact circles around reflowed multi-line text are not portable. The recommended hybrid degradation is an honest platform constraint.
4. **“Any OpenAI-compatible API” is not a conformance guarantee.** Servers differ in tools, JSON Schema, streaming, error shapes, and token fields. Profiles plus capability overrides and prompt fallback provide breadth; the project should publish tested endpoints/versions, not promise every implementation.
5. **Provider capability autodetection can cost money.** Prefer static profiles and failure-informed one-time downgrade; never spray multiple trial completions. Doctor calls are explicit.
6. **Concurrency conflicts with sequential running context.** Windowed batches trade perfect immediate continuity for throughput. Default sequential mode and saved checkpoints make the tradeoff user-controlled.
7. **Vector complexity can bloat books.** Path simplification, filled-pressure batching, cache reuse, and hard budgets need quantitative gates before 1.0.
8. **Exact reproducibility has boundaries.** A saved semantic plan plus scene cache is reproducible; rerunning a remote LLM is not. Algorithm versions and seeds must be stored, and old scene versions either remain renderable or are migrated explicitly.
9. **Native PDF annotations versus authentic appearance is a real tradeoff.** Visible vector ink should be the default; optional native semantic annotations preserve accessibility/editability without dictating geometry.
10. **Security/privacy:** book text leaves the machine for hosted providers. The CLI must state endpoint/provider, avoid telemetry, document retention implications, redact logs, bind local endpoints only as users configure them, and never persist keys.
11. **Output ownership and fan-project positioning need review.** Provider terms, source-book copyright, generated marginalia, project naming, and gallery assets are separate concerns. Documentation must not imply users may redistribute annotated copyrighted books.
12. **Backward compatibility:** splitting modules and plan v2 must not strand v1 JSON or existing Python users. Re-exports and migrations should last through a documented deprecation window, but private renderer helpers are not stable API.

## 11. Architectural decisions summary

- Keep the simple one-request-per-unit pipeline and direct, auditable integration; use a thin `httpx` provider layer, not LiteLLM/LangChain.
- Treat Anthropic and OpenAI-compatible HTTP as the only two wire protocols; OpenRouter/Ollama/LM Studio are profiles.
- Prefer forced tool/function output, then strict JSON Schema, then constrained prompt-and-parse; always finish with Pydantic validation.
- Persist semantic plans and generation reports; preserve and generalize `AllPagesFailedError` and partial `failed_pages` behavior.
- Decouple semantic plan, resolved layout, and renderer-neutral `InkScene` so paid generation is reusable.
- Ship deterministic authored centerline trajectory handwriting; add licensed ONNX synthesis only as an optional enhancement.
- Generate rough marks, variable-width connectors, doodles, and letters once; translate the same paths to PyMuPDF and SVG.
- Accept an explicit EPUB hybrid degradation because reflow prevents universal fixed-geometry ink.
- Close the existing audit before expansion, then deliver provider breadth, layout, handwriting, cross-surface rendering, scale, and release in that order.
